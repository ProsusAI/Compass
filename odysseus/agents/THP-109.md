# THP-109 — Design clarification request templates

**Type:** Task  
**Status:** To Do  
**Epic:** [THP-68](https://prosus-thymo-thesis.atlassian.net/browse/THP-68) — User input agent  
**Jira:** [THP-109](https://prosus-thymo-thesis.atlassian.net/browse/THP-109)

## Description

Define the format and content of the structured messages the agent sends back to the user when a blocking gap is detected. Templates should specify what information is being requested, why it is required, and what format the answer should take.

These templates are embedded in the gap report output (THP-72) under the relevant blocking gap entry, so that the MCP server can surface them directly to the user as a structured clarification prompt.

## What to build

Produce one template per blocking field from THP-108. Each template must contain:

1. **Gap identifier** — which field is missing (matching field names from THP-70).
2. **Explanation** — why this field is required and what happens if it is absent.
3. **Request phrasing** — the exact message surfaced to the user, written in plain language.
4. **Format guidance** — instructions on the expected answer format to reduce ambiguous follow-ups.

Example templates:

---

**Missing: `routing_dataset`**

> Your submission is missing a routing dataset. This is required for the pipeline to analyze routing patterns and evaluate prompt quality — no default can substitute real labeled data.
>
> Please provide a routing dataset as a JSONL file path or inline JSONL content. Each record must contain at minimum:
> - `input`: the query or request being routed
> - `expected`: the correct routing decision (model tier or route label)
>
> Example record: `{"input": "Write a short poem", "expected": "haiku-3"}`

---

**Missing: `problem_description`**

> Your submission is missing a problem description. The Analysis Agent uses this to understand the routing context and extract decision patterns — without it, the analysis cannot be grounded in your specific use case.
>
> Please provide a plain-text description of your routing problem. It should explain: what types of requests are being routed, what the available model tiers are, and what trade-offs matter most (e.g. cost vs. quality).

---

> **Note:** `target_metrics` was reclassified as non-blocking in THP-108. When absent, the pipeline defaults to `["accuracy"]` with no threshold (see THP-71). No clarification template is needed for this field.

---

Also define:

- **Multi-gap handling** — how to present multiple blocking gaps in a single response (list all at once rather than one at a time to minimize round trips).
- **Re-submission flow** — what the user should do to resume the pipeline after providing the requested information.
