# THP-115 — Define holdout set access control

**Type:** Task  
**Status:** To Do  
**Epic:** [THP-76](https://prosus-thymo-thesis.atlassian.net/browse/THP-76) — Eval runner agent  
**Jira:** [THP-115](https://prosus-thymo-thesis.atlassian.net/browse/THP-115)

## Description

Specify where and how the dev-only constraint is enforced during the refinement loop. `RunConfig.data_split: Literal["dev", "holdout"]` already exists, and `DatasetManager.load(path, split)` enforces the split at load time. This task decides the enforcement strategy and documents the boundary.

## What to design

1. **Enforcement point** — the `run_eval` MCP tool (THP-114) must hardcode `data_split="dev"` internally; this field is never exposed as a tool parameter. Decide whether to enforce at tool level only, or also at `RunConfig` construction.
2. **Agent-visible error** — what the agent sees if it somehow tries to request holdout data.
3. **Legitimate holdout access** — how and when the holdout eval is triggered once the optimization loop exits (which agent, which tool, under what conditions). A separate `run_holdout_eval` tool is the preferred approach — it must be absent from the Eval Runner agent's tool list.

## How it links with the rest of the codebase

| Touch point | Detail |
