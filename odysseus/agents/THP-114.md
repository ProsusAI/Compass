# THP-114 — Design the run_eval MCP tool that wraps the Run Controller

**Type:** Task  
**Status:** To Do  
**Epic:** [THP-76](https://prosus-thymo-thesis.atlassian.net/browse/THP-76) — Eval runner agent  
**Jira:** [THP-114](https://prosus-thymo-thesis.atlassian.net/browse/THP-114)

## Description

Design the MCP tool the Eval Runner agent LLM calls to trigger an evaluation run. The Run Controller is already implemented as `async def run(config: RunConfig, deps: RunDependencies) -> RunReport` in `odysseus/eval/controller.py`; this task defines the tool that wraps it.

## What to design

1. **Tool name and input schema** — expose `prompt_version: str` and `data_source: str` as parameters. `data_split` must NOT be a parameter (always hardcoded to `"dev"` — see THP-115).
2. **RunDependencies wiring** — which concrete implementations are assembled in `mcp.py`: `LiteLLMBackend` (THP-113), `FilePromptManager` (THP-87), `JsonDatasetManager` (THP-90), `DefaultMetricsEngine` (THP-88), `JsonResultsCollector` (THP-91).
3. **Return value** — what the tool returns to the LLM: a serialized score report in the format defined by THP-116.

## How it links with the rest of the codebase

| Touch point | Detail |
