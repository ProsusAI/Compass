# THP-145 — Implement full dataset validation logic

**Type:** Task

## Description

Implement the end-to-end validation logic executed by the Data Validation agent against the user-submitted routing dataset. This is the core implementation task for THP-73 — it takes the data format spec (THP-80) and output format (THP-81) as inputs and produces a fully populated data quality report.

## What to build

Implement validation logic covering:

1. **Schema conformance** — validate against the format defined in THP-80:
   - Required fields present (`input`, `expected`).
   - Correct types per field.
   - No structural violations (malformed JSONL, missing keys, null values where disallowed).

2. **Statistical checks**:
   - Label distribution counts per routing class.
   - Null field detection and count.
   - Row count per class.
   - Query length distribution (min, max, mean, p95).

3. **Volume adequacy**:
   - Minimum rows per class (threshold from THP-80 / THP-69 alignment).
   - Overall row count threshold.
   - Flag classes that fall below minimum coverage.

4. **Missing signal types**:
   - Query diversity gaps (e.g. all examples for a class look semantically identical).
   - Underrepresented routing cases relative to the user's problem description.

5. **Data quality report** — produce the report structure defined in THP-81:
   - Schema check results.
   - Statistical summary.
   - Volume adequacy verdict per class.
   - Missing signal flags.

6. **Data collection suggestions** — generate a prioritised list of additional data to collect, ranked by expected impact on routing performance, tailored to the user's problem description.

Suggested file: `odysseus/agents/data_validation_logic.py` (or as part of the Data Validation agent implementation).
