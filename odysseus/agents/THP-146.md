## Description

Integration test of the whole brainstorming part of the pipeline. First run with a data analyst mock, rerun when complete.

This test exercises the full User Input agent flow end-to-end: from raw user submission through gap detection, default application or clarification request, and production of the validated input report — without real LLM API calls.

## What to build

Suggested file: `tests/test_user_input_agent.py`

### Test cases

1. **Complete submission — proceed** — submit a fully specified input (dataset, problem description, target metrics all present and valid). Assert `status: "proceed"`, all confirmed inputs populated, empty gap report.

2. **Missing optional field — proceed with defaults** — submit with `target_metrics` absent. Assert `status: "proceed_with_defaults"`, default metric applied, gap report entry with `classification: "non-blocking"` and correct `default_applied` value.

3. **Missing required field — clarification required** — submit without `routing_dataset`. Assert `status: "clarification_required"`, gap report entry with `classification: "blocking"`, clarification template text present.

4. **Multiple blocking gaps** — submit with both `routing_dataset` and `problem_description` absent. Assert all blocking gaps surfaced together in a single response (not one-at-a-time).

5. **Mixed blocking and non-blocking gaps** — submit with `routing_dataset` missing (blocking) and `evaluation_threshold` absent (non-blocking). Assert the response halts on the blocking gap; non-blocking gap is included in the report but does not prevent clarification.

6. **Malformed dataset** — submit with `routing_dataset` present but structurally invalid (missing `expected` field). Assert this is treated as a blocking gap with an appropriate clarification message.

### Setup

- Use `tmp_path` for any file output.
- Mock the LLM client to return deterministic responses without making real API calls.
- Use small synthetic datasets (3–5 records).

### Data analyst mock

First run of this test uses a mock data analyst response. Once the Data Validation agent (THP-73) is complete, rerun against the real implementation.
