# THP-108 — Define blocking vs. non-blocking gap taxonomy

**Type:** Task  
**Status:** In Review  
**Epic:** [THP-68](https://prosus-thymo-thesis.atlassian.net/browse/THP-68) — User input agent  
**Jira:** [THP-108](https://prosus-thymo-thesis.atlassian.net/browse/THP-108)

## Description

Define the classification rules that determine which missing input fields halt the pipeline (blocking gaps) vs. which can be filled with a sensible default and proceed (non-blocking gaps). For each field, the taxonomy should state the classification and the rationale — e.g. missing routing data is always blocking because no default can substitute it, while a missing evaluation threshold is non-blocking because a standard value applies.

This taxonomy is the core decision logic the agent relies on when producing the gap report.

## What to build

Produce a taxonomy table covering every field from THP-70 (required and optional), with the following columns:

| Field | Classification | Rationale | Default (if non-blocking) |
|---|---|---|---|
| `routing_dataset` | Blocking | No default can substitute real labeled routing data | — |
| `problem_description` | Blocking | Analysis agent cannot extract patterns without it | — |
| `target_metrics` | Non-blocking | Accuracy is the most interpretable baseline metric; defaulting to it lets the pipeline proceed | THP-71 |
| `evaluation_threshold` | Non-blocking | Standard threshold (e.g. 0.80 accuracy) is a reasonable default | THP-71 |
| `data_split_ratio` | Non-blocking | 80/20 split is a well-established default | THP-71 |
| `max_iterations` | Non-blocking | A default ceiling prevents unbounded runs | THP-71 |

Also define:

1. **Blocking criteria** — the general rule for what makes a gap blocking (cannot be reasonably defaulted; no surrogate exists; downstream agent output quality degrades catastrophically without it).
2. **Non-blocking criteria** — the general rule for what makes a gap non-blocking (a principled domain default exists; the user can review and override the assumed value later).
3. **Partial data handling** — rules for dataset fields that are present but malformed or below minimum volume (these may be conditionally blocking depending on severity).
