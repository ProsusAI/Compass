## Description

Write the final system prompt for the User Input agent, incorporating the static context (THP-69), defaults table (THP-71), output format (THP-72), blocking vs. non-blocking gap taxonomy (THP-108), and clarification request templates (THP-109). The prompt must handle all three outcomes: proceed with complete input, proceed with defaults applied, or halt and request clarification.

## What to build

Write the system prompt that is loaded by the User Input agent at runtime. The prompt must:

1. **Set the agent's role** — the agent is the pipeline entry gate; its job is to validate the user's submission and produce a validated input report (THP-72 schema) before any other agent runs.

2. **Embed the static context** (from THP-69):
   - Definition of a complete problem specification.
   - List of required and optional fields with acceptable formats.
   - Minimum data volume thresholds.

3. **Embed the gap taxonomy** (from THP-108):
   - Per-field blocking vs. non-blocking classification.
   - Decision rule: if any blocking gap → `clarification_required`; if only non-blocking gaps → `proceed_with_defaults`; if none → `proceed`.

4. **Embed the defaults table** (from THP-71):
   - Lookup table the agent uses to fill non-blocking gaps.
   - Instruction to record each assumed default in `assumed_defaults` with its user-facing note.

5. **Embed the clarification templates** (from THP-109):
   - One template per blocking field.
   - Instruction to collect all blocking gaps and surface them together in a single `clarification_required` response (no one-at-a-time drip).

6. **Specify the output format** (from THP-72):
   - The agent must produce a Markdown file following the validated input report template (THP-72).
   - The report is human-readable and consumed by downstream LLM agents via their prompt context.

### Handling all three outcomes

**Outcome A — `proceed`:**
All required fields are present and valid. Produce the report with `**Status:** proceed`, Confirmed Inputs fully populated, no Gap Report or Assumed Defaults sections.

**Outcome B — `proceed_with_defaults`:**
Required fields are present; one or more optional fields are absent. Apply defaults from the lookup table. Produce the report with `**Status:** proceed_with_defaults`, Gap Report entries with `classification: "non-blocking"`, and an Assumed Defaults table listing each defaulted field.

**Outcome C — `clarification_required`:**
At least one required field is missing or malformed. Collect all blocking gaps. Produce the report with `**Status:** clarification_required`, Gap Report entries with `classification: "blocking"` and the corresponding clarification template text. Do not proceed with any downstream steps.
