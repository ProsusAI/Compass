## Description

Write the final system prompt for the Data Validation agent. The prompt assembles all four context artifacts into a single self-contained instruction set that turns any MCP-connected LLM into the Data Validation agent.

## What to build

Write a system prompt (`prompts/data_validation_system.md`) that incorporates:

1. **Data format spec (THP-80)** — so the agent knows what schema to validate against (required fields, types, structural constraints).

2. **Output format and code generation context (THP-81)** — so the agent:
   - Knows what structure to produce in the data quality report.
   - Has canonical code examples for generating analysis code (label distribution, null detection, row counts, query length distribution).

3. **Routing rationale schema (THP-82)** — so the agent can annotate examples with structured rationale cards and detect missing signal types using the ambiguity taxonomy.

4. **Routing dataset quality context (THP-84)** — so quality judgements are grounded in domain-specific criteria (label balance, query diversity, boundary coverage, edge cases) rather than generic thresholds.

### Prompt structure

1. **Role & mission** — The agent is the pipeline's data quality gate. It receives a dataset path and problem description from the validated input report (THP-72) and produces a data quality report before the Routing Analysis agent (THP-74) runs.

2. **Validation procedure** — Step-by-step instructions:
   a. Load the JSONL dataset from the provided path.
   b. Generate and execute analysis code using the code generation context.
   c. Run schema conformance, statistical, volume, and diversity checks.
   d. Identify missing signal types using the routing rationale schema.
   e. Assess overall quality against the routing dataset quality criteria.

3. **Data quality report** — Instructions to produce the report in the structure defined by THP-81, including data collection suggestions prioritised by expected impact on routing performance tailored to the user's problem description.

4. **Blocking issue escalation** — If the dataset has structural violations (e.g. missing `expected` field, malformed JSONL), the agent surfaces the issue back to the User Input agent using the "fix" question type rather than producing a partial report.

Suggested file: `prompts/data_validation_system.md`
