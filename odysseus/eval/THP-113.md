## Description

Implement the backend registry component that normalises response formats across OpenAI, Anthropic, and custom endpoints. Each backend entry in the config defines its endpoint URL, authentication method, model identifier, and limit profile. The client abstraction layer ensures the scoring layer receives a consistent response object regardless of which backend was selected. This is a prerequisite for the Concurrency Engine (THP-89).

## What to build

Implement one or more concrete classes that satisfy the `Backend` protocol defined in `odysseus/eval/protocols.py`:

```python
class Backend(Protocol):
    @property
    def model_name(self) -> str: ...

    async def call(
        self, prompt: str, example: Example
    ) -> tuple[dict[str, Any], TokenUsage]: ...
```

### LiteLLM backend (primary implementation)

The design spec (THP-92) mandates **LiteLLM** as the multi-provider abstraction layer. Add `litellm` to `pyproject.toml` dependencies.

```python
# odysseus/eval/backends/litellm_backend.py
import litellm

class LiteLLMBackend:
    def __init__(self, model: str, **kwargs: Any) -> None:
        self._model = model
        self._kwargs = kwargs  # api_key, base_url, etc.

    @property
    def model_name(self) -> str:
        return self._model

    async def call(self, prompt: str, example: Example) -> tuple[dict[str, Any], TokenUsage]:
        response = await litellm.acompletion(
            model=self._model,
            messages=[{"role": "user", "content": prompt}],
            **self._kwargs,
        )
        # Normalise to TokenUsage (Anthropic-style disjoint fields)
        usage = response.usage
        token_usage = TokenUsage(
            input_tokens=usage.prompt_tokens,
            cached_tokens=getattr(usage, "cache_read_input_tokens", 0),
            output_tokens=usage.completion_tokens,
        )
        output = {"content": response.choices[0].message.content}
        return output, token_usage
```

### Registry

Maintain a simple registry (`dict[str, type[Backend]]` or factory functions) so the MCP layer can look up backend classes by the `backend` label in `RunConfig`. The `backend` field in `RunConfig` is a label for record-keeping; the actual backend instance is injected into `RunDependencies` by the caller (MCP or test).

### Response normalisation contract

`TokenUsage` uses **Anthropic-style disjoint fields**:
- `input_tokens` — non-cached prompt tokens
- `cached_tokens` — tokens served from cache (not double-counted with `input_tokens`)
- `output_tokens` — generated tokens

LiteLLM provider responses must be normalised to this convention before constructing `TokenUsage`. Total cost-bearing tokens = `input_tokens + cached_tokens + output_tokens`.

Suggested directory: `odysseus/eval/backends/`

## How it links with the rest of the codebase

| Touch point | Detail |
|---|---|
| `odysseus/eval/protocols.py` | Defines the `Backend` protocol this class must satisfy (`model_name` property + `async call()`). |
| `odysseus/eval/models.py` | `call()` must return `(dict[str, Any], TokenUsage)`. `TokenUsage` (disjoint fields) is the normalisation target. |
| `odysseus/eval/controller.py` | `_eval_with_retry()` calls `backend.call(prompt, example)` inside `asyncio.wait_for(...)`. The `backend` is injected via `RunDependencies.backend`. |
| `odysseus/eval/pricing.py` | `compute_cost(pricing, usage)` uses `TokenUsage` to compute dollar cost. `pricing` is a `ModelPricing` loaded from the backend profile. |
| `odysseus/eval/rate_limiter.py` | Token counts from `TokenUsage` are passed to `rate_limiter.consume_tokens()` post-call. |
| `odysseus/mcp.py` | The MCP tool will construct a concrete `LiteLLMBackend` (or registry lookup) and inject it into `RunDependencies` before calling `run()`. |
| `pyproject.toml` | Add `litellm` as a runtime dependency via `uv add litellm`. |
